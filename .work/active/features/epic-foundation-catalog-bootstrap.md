# Catalog Bootstrap (fetch-on-first-run)

## Brief

Get the Kilter catalog onto the client on first launch. A BoardLib-produced `kilter.db`
snapshot is hosted as a static artifact; on first run the app fetches it into OPFS (via the
SQLite worker), shows a first-run loading state, and thereafter reads it offline.

Covers: a `/ml` (or script) step that runs BoardLib to produce `kilter.db` and publishes it
as a static, versioned artifact; the client-side first-run flow (detect empty OPFS → fetch
snapshot → write to OPFS via the worker → ready); a loading/progress UX for the one-time
download; and a version marker so later catalog-sync (separate epic) can update it. Does NOT
implement incremental sync (epic-catalog-sync) or browsing UI.

## Epic context
- Parent epic: `epic-foundation`
- Position: completes the read path — depends on sqlite-readpath; last foundation feature.

## Inherited design decisions
- Fetch-on-first-run (not bundled): lean app, one-time network fetch into OPFS, then offline.
- Snapshot generated by BoardLib (in `/ml` or a CI step) and hosted statically.
